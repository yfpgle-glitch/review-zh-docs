# 中文文档审校

这个版本用于审阅 AI 生成或 AI 辅助生成的中文 Markdown 文档。它关注文档质量，不做风格包装，也不是 AI 检测器。

适合检查：

- 需求文档、PRD、功能说明
- 项目 README、项目说明、模块说明
- 技术方案、架构方案、实施计划
- 任务拆解、开发路线图、验收清单
- 周报、复盘、会议纪要、工作总结
- Codex、Claude、ChatGPT 生成的 `.md` 草稿

## 它主要看什么

- 文档是否具体、可执行、可验收
- 标题和列表是否真的承载信息
- 需求是否缺少角色、输入、输出、状态、边界、异常和验收标准
- 方案是否缺少取舍、依赖、风险、回滚和测试方式
- README 是否缺少运行命令、目录说明、环境配置和下一步
- 是否存在 AI 常见套话、空话、伪总结和 ChatGPT 对话痕迹

## 默认行为

- 说"看看、检查、审一下"时，只审阅，不改文件。
- 说"帮我修改、直接改、整理一下"时，才编辑文件。
- 没有来源的信息标成 `待确认`，不替原文补看似合理的细节。
- 如果没有核对代码、资料或命令，会在结论里说明。

## 基础用法

审阅一份 Markdown 文档：

```text
/review-zh-docs 帮我审一下 docs/requirements.md，看看有没有空话和不可执行的地方
```

直接修改文档：

```text
/review-zh-docs 帮我修改 README.md，让它更适合新人接手项目
```

重写某一节：

```text
/review-zh-docs 帮我把这个方案稿里的"实施计划"一节改得更具体，保留原意
```

## 输出方式

审阅模式通常输出：

```markdown
## 主要问题
- [严重] `path/to/file.md:42` 问题描述。影响：... 建议：...
- [中等] `path/to/file.md:78` 问题描述。建议：...

## 缺失信息
- 待确认：...

## 可保留内容
- ...
```

修改模式会尽量局部改，不会无端重排整篇。遇到缺少来源的信息，会用 `待确认：...` 标出来，而不是自己编。

## 评分标准

| 维度 | 评估问题 | 得分 |
|------|----------|------|
| 可执行性 | 读者是否知道下一步做什么 | /10 |
| 可验收性 | 是否有边界、状态、成功标准 | /10 |
| 结构有效性 | 标题、列表、表格是否承载信息 | /10 |
| 来源可靠性 | 是否忠于材料，是否避免编造 | /10 |
| 表达克制 | 是否删掉套话、铺垫和空总结 | /10 |
| 总分 |  | /50 |

- 45-50 分：可以直接交接或进入执行。
- 35-44 分：主体可用，需要补边界或删套话。
- 低于 35 分：不建议直接使用，应回到原始材料重写。

## 常见 AI 文档问题

- 标题很多，但每节只有一句空话。
- 列表项都是"优化、完善、提升、加强"，没有对象和完成标准。
- 需求写了"支持上传文件"，但没写文件类型、大小、重复上传、失败处理。
- 方案直接说"采用某技术"，但没写为什么不用其他方案。
- README 写了项目很先进，但没有运行命令和关键目录。
- 总结只写"显著提升、持续优化、奠定基础"，没有产物和下一步。

## 注意

这个技能的目标是让 AI 生成的 Markdown 文档更能指导真实工作。它会优先指出缺失信息，而不是替文档编造细节。
